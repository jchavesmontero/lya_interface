# Scripts: from a cup1d configuration to a Cobaya MCMC on NERSC

The example throughout is `hires_forestflow` (DESI DR1 QMLE3 + Karacayli2022,
`forest_mpg_gp`, 53 sampled parameters). Paths are relative to the
`lya_interface` checkout; cup1d, ForestFlow and LaCE are sibling checkouts.

| File | What it does |
|---|---|
| `config_from_cup1d.py` | Writes the interface YAML equivalent to a native cup1d YAML, or syncs the `As`/`ns` priors of hand-written examples. |
| `run_mcmc.py` | Runs a Cobaya MCMC from a production YAML: `--test` (short chain), production (MPI, resumes), `--status` (convergence). |
| `thread_scaling.py` | Times one likelihood call against the number of OpenMP threads, to choose chains x threads per node. |
| `nersc/mcmc_job.sh` | Slurm job for Perlmutter CPU nodes that resubmits itself until the run converges. |

## Workflow

### 1. Interface configuration (only when the cup1d YAML changes)

```bash
python scripts/config_from_cup1d.py ../cup1d/configs/hires/hires_forestflow.yaml \
    examples/hires_forestflow_evaluate.yaml
```

The generated YAML points `native_config` at the cup1d file, so data, emulator
and numerical settings come from cup1d: `k_rebin_factor: 32`, `n_k_emu: 64`,
`shared_k_grid: true` (one fine k grid per redshift for DESI and the high
resolution data), `cosmo_prior_nsigma: 2`, `syst_data_labels`. Do not edit it
by hand; regenerate it. It is also (re)generated by the validation notebook
(`REGENERATE_CONFIG = True`).

### 2. Validation (after changing cup1d, ForestFlow, lya_interface or the config)

* `notebooks/tests/hires_forestflow_validation`: native cup1d and the
  interface must give the same rebinned P1D (|ratio - 1| < 1e-4 per bin).
  Expect a ~5e-5 offset and |dchi2| up to ~0.1 away from the best fit: native
  LaCE asks CAMB for CMB outputs and Cobaya does not, which changes the linear
  power at k < 1/Mpc by up to 1e-3 (both within CAMB's accuracy).
* `notebooks/tests/linear_power_rescaling`: As/ns rescaling of the linear
  power in both pipelines against direct CAMB runs.
* `../cup1d/notebooks/validation/convergence_shared_grid`: rebinning
  convergence with two samples. Result: shared 32/64 within |dchi2| < 0.03 per
  data set of the reference (the old separate grids had a +0.022 bias on
  Karacayli2022); 64/64 is within 0.002 but costs more.

### 3. Best fit, proposal covariance and production YAML (laptop)

Run `notebooks/wip/hires_forestflow_cobaya_mcmc` (sections 1 and 2). Everything
goes to `output/hires_forestflow/cobaya_mcmc/` (`OUT_DIR`, not tracked by git):

| File | Content |
|---|---|
| `best_fit.npy` | Best fit (minimized from the global IC if missing) and Gauss-Newton errors. Reused on later runs. |
| `gauss_newton_covmat.txt` | Regularized covariance from those errors, physical units. Rebuilt every run. |
| `proposal_covmat.txt` | Covariance given to the sampler, **unit-cube units** (`<name>_cube`). |
| `cobaya_mcmc.yaml` | Production YAML: `interface_base`, `sample_in_unit_cube: true`, starting ball, sampler, `output: chains/mcmc`, `resume: true`. |

Proposal covariance, in order of preference: `COVMAT_FROM` (e.g. the learned
covariance of the full-data run, for a data split), the covariance learned by a
previous production run (`chains/mcmc.covmat`), the Gauss-Newton one. Learned
covariances are in unit-cube units, i.e. relative to the prior ranges: reuse
them only between runs with the same priors.

Sampler settings: `learn_proposal: true`, `drag: false`,
`oversample_power: 0` (the likelihood costs about as much as the emulator, so
Cobaya's speed blocks bring nothing), `proposal_scale: 1.9`,
`Rminus1_stop: 0.02`, `Rminus1_cl_stop: 0.2`.

**Unit cube.** Cobaya samples every parameter in [0, 1] (`x_cube`) and computes
`x = min + (max - min) * x_cube`, as native cup1d does. Priors stay flat in the
physical parameters, which are written to the chain. Without it, the
covariance of `As` (~1e-9) next to order-one parameters fails Cobaya's
positive-definiteness check (`The given covmat is not a positive-definite ...`).
Use `sample_in_unit_cube: true` for Cobaya's `minimize` too.

### 4. Test run on the laptop

```bash
python scripts/run_mcmc.py output/hires_forestflow/cobaya_mcmc/cobaya_mcmc.yaml --test
```

A single chain of 200 accepted points (`--test-samples`) in
`OUT_DIR/test/`, overwriting the previous test. It prints the acceptance rate,
the time per step and a forecast for `--target-steps` steps per chain (an
assumption until the first production run). Check the full path with
section 4 of the notebook (it reads `TEST_PREFIX`): reload, traces, triangle
plot. In a 200-point test As/ns may accept few or no steps; that is normal,
but if their trace never moves over a longer test, check the proposal
covariance.

### 5. NERSC setup (once)

1. Clone `cup1d`, `lya_interface`, `ForestFlow`, `LaCE` side by side (same layout
   as on the laptop: `OUT_DIR` paths are relative).
2. Environment with the four packages installed editable, plus Cobaya, and
   mpi4py built against Cray MPICH:
   ```bash
   module load python
   conda activate lace
   MPICC="cc -shared" pip install --force-reinstall --no-cache-dir --no-binary=mpi4py mpi4py
   ```
3. Check out the analysis branches: cup1d `high_res`, lya_interface `hires`,
   ForestFlow `high_res`, LaCE `hires`. Record the four commit SHAs.
4. Copy the files that are **not in git** (both are git-ignored), keeping the
   same relative paths:
   ```bash
   # -R keeps the paths relative to the current folder: run it from igmhub
   cd ~/Proyectos/projects/lya/igmhub
   # destination: the NERSC folder containing the cup1d and lya_interface checkouts
   rsync -avR lya_interface/output/hires_forestflow/cobaya_mcmc/{cobaya_mcmc.yaml,proposal_covmat.txt,best_fit.npy,gauss_newton_covmat.txt} \
              cup1d/data/ics/DESIY1_QMLE3_Karacayli2022_forest_mpg_gp_ic_global.npy \
              <user>@perlmutter.nersc.gov:<igmhub on NERSC>/
   ```
   The production run needs only `cobaya_mcmc.yaml` and `proposal_covmat.txt`.
   `best_fit.npy` is for the notebook. The IC file is read by native cup1d
   (validation notebooks); without it cup1d silently starts from the fiducial
   values instead.
5. Everything else the analysis reads is in git (checked by tracing the files
   opened by both pipelines): the P1D data (`cup1d/data/p1d_measurements/`
   Karacayli2025 DESI fits file and Karacayli2022), the GP emulator
   (`ForestFlow/data/gp_emulators/forest_mpg_gp.pkl`), its covariance
   (`ForestFlow/data/covariance/l1O_cov_forest_mpg_gp.npy`), the training-set
   cosmologies and IGM histories (`LaCE/data/sim_suites/Australia20/`), the
   cup1d defaults and the hires config.
6. Package versions. The GP emulator is a scikit-learn pickle: use the same
   scikit-learn (1.5.2) to load it. Use the same CAMB (2.0.0), so the linear
   power matches. Versions on the laptop: numpy 2.5.1, scipy 1.18.0,
   scikit-learn 1.5.2, camb 2.0.0, cobaya 3.6.2, getdist 1.7.7, torch 2.13.0.

### 6. Test on the login node

```bash
cd <lya_interface on NERSC>
export RUN_DIR=$PWD/output/hires_forestflow/cobaya_mcmc   # used in the commands below
OMP_NUM_THREADS=4 python scripts/run_mcmc.py $RUN_DIR/cobaya_mcmc.yaml --test --test-samples 50
```

Keep it short: login nodes are shared.

**Chains are not emcee walkers.** emcee walkers form one ensemble and need
~2 x 53 of them. A Cobaya chain is an independent Metropolis chain (one per MPI
rank) with a proposal covariance learned from all of them; a handful (4-16) is
enough to measure convergence. More chains give more samples per hour; faster
chains (more threads) burn in sooner.

### 8. Test job, then production

`scripts/nersc/mcmc_job.sh` is set up for account `desi`, 64 chains x 1
thread per node (`--ntasks-per-node=64`, `--cpus-per-task=4`: two cores per
chain; threads do not help, 0.134 s per call for 1-32 threads), and the NERSC
`LYA_INTERFACE`. Check `activate_environment` and `MAX_JOBS` at its top.

**Test job** (debug queue, the whole path with 64 chains): 1000 accepted points
per chain (`TEST_SAMPLES`) in `RUN_DIR/test/` (overwritten), with convergence
checks every `5d` accepted points so the checkpoint, the learned covariance
and the progress file are written. No resubmission. The log ends with the
files in `test/` and a status report that reloads the chains:

```bash
sbatch --qos=debug --time=00:30:00 --export=ALL,MODE=test scripts/nersc/mcmc_job.sh
```

Check in `lya_mcmc-<jobid>.out`: `test/mcmc.1.txt` ... `mcmc.64.txt`,
`mcmc.covmat`, `mcmc.checkpoint`, `mcmc.progress` written; "reloaded: N
points" with the physical columns `As`, `ns`, `Delta2star`; no errors. Same
check by hand: `python scripts/run_mcmc.py $RUN_DIR/cobaya_mcmc.yaml --test --status`.

**Production:**

```bash
sbatch scripts/nersc/mcmc_job.sh
```

Each job queues its successor (`afterany`, so it starts even if this one hits
the time limit), runs Cobaya (which resumes from its checkpoint), and cancels
the successor once the run has converged. At most `MAX_JOBS` jobs are chained.
Logs: `lya_mcmc-<jobid>.out`.

### 9. Monitoring

```bash
python scripts/run_mcmc.py $RUN_DIR/cobaya_mcmc.yaml --status   # exit 0 converged, 1 not yet, 2 not started
squeue -u $USER
```

Cobaya's log prints the acceptance rate (aim for ~0.2-0.3) and R-1 at every
convergence check. Outputs in `RUN_DIR/chains/`: `mcmc.<i>.txt` (chain of rank
i), `mcmc.covmat` (learned covariance), `mcmc.checkpoint`, `mcmc.progress`,
`mcmc.updated.yaml`.

**R-1 (Gelman-Rubin).** Ratio of the spread of the parameter means between
chains to the spread of the samples within a chain, for the worst combination
of parameters. It goes to 0 when every chain has forgotten its starting point
and samples the same posterior; at 0.02 the means are known to about 0.14
sigma. The run stops when R-1 of the means < `Rminus1_stop` and R-1 of the 95%
limits < `Rminus1_cl_stop`. To tighten to 0.01 afterwards: set
`Rminus1_stop: 0.01` in `cobaya_mcmc.yaml` and `sbatch` again; it resumes.

### 10. Analysis

Section 4 of the MCMC notebook, with `TEST_PREFIX` replaced by
`OUT_DIR / "chains/mcmc"`: `cobaya.load_samples(prefix, skip=0.3,
to_getdist=True)`. Star parameters (`Delta2star`, `nstar`, `alphastar`) are
blinded. The comparison with the native emcee chains is still to do.

## Troubleshooting

* **`The given covmat is not a positive-definite ...`**: the production YAML
  lacks `sample_in_unit_cube: true`, or `proposal_covmat.txt` is in physical
  units. Rerun sections 1-2 of the notebook.
* **Every point rejected / chi2 = inf**: run the validation notebook; it reports
  the rejection reason (e.g. k outside the emulator coverage).
* **A parameter never moves in a long test**: check its proposal width in
  `proposal_covmat.txt` against its prior range (the notebook skips covariances
  with sigma > 0.25 of the prior range).
* **Repeated overflow warnings**: shown once per process and only on MPI rank 0
  (`cup1d.utils.warn_once`).
