# lya_interface

Full **cup1d P1D data likelihood** in Cobaya: CAMB → immutable cosmology →
ForestFlow mean Arinyo coefficients → uncontaminated P1D → native cup1d
contaminants, resolution, rebinning and correlated covariance.

cupix remains deferred. An optional Vega adapter can consume the same
ForestFlow coefficient bundle at Vega's effective redshift. It deliberately
retains Vega's fixed native linear template, so this is a hybrid approximation
rather than a cosmology-consistent template replacement. Do not combine this
with the compressed `cobaya_lya_p1d` likelihood for the same data.

## Install and run

Use Python 3.12+ and compatible sibling checkouts. cup1d **must include the new
`cup1d.likelihood.external` API delivered alongside this change**. From the
sibling-repository parent:

```bash
python -m pip install -e ./LaCE -e ./ForestFlow -e ./cup1d
python -m pip install -e './lya_interface[test]'
cd lya_interface
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python examples/evaluate_point.py
python examples/evaluate_point.py examples/cup1d_mcmc.yaml
python examples/evaluate_point.py examples/cup1d_mle.yaml
```

The three complete YAMLs also work with `cobaya-run` from this repository root.
The Python loader resolves example paths when running from another directory.
`--point` accepts a JSON mapping overriding sampled reference values, `--output`
overrides a sampler's output prefix, and `--provenance /path/to/file.json` saves
revisions, checksums, settings and the resolved registry/request. Create its
parent directory first.

`examples/vega_native_reference.yaml` is a reproducible adapter reference for
the supplied Lyα Vega configuration. It exercises Vega in native-template mode
with `chi2(include_priors=False)` and migrates its Gaussian priors to Cobaya
once. It is not a ForestFlow-coupled scientific fit. Coupled mode requires a
ForestFlowTheory configuration, `small scale nl = forestflow` in the Vega data
INI, a documented fixed template `h` (the supplied template has H0=67.36), and
the fixed-template/effective-redshift/zero-cross-covariance assumptions stated
in the architecture document.

`examples/vega_forestflow_main.ini` and
`examples/vega_lyaxlya_forestflow.ini` are the non-destructive derived Vega
INI pair for coupled mode. They retain the native data, distortion, metal,
peak/smooth and template choices while selecting the new correction.
`examples/joint_validation_vega_forestflow.yaml` combines those INIs with the
small P1D validation fixture; it is a smoke-test example, not a calibrated
CM2026 production fit.

The examples inherit cup1d's **CM2026 baseline**, changing the emulator alias
from `lace_mpg` to `forest_mpg`. They use DESIY1_QMLE3, rebinning factor 8,
four-node MPG-central IGM histories, the full native contaminant/resolution
configuration, statistical covariance factor 1.05 and full emulator covariance.
All 53 baseline parameters are sampled using exported native fiducial values
and bounds. The native YAML is a sparse override of maintained cup1d defaults;
the Cobaya parameter export was checked against native parameter definitions.

The calibrated covariance
`ForestFlow/data/covariance/l1O_cov_forest_mpg_fix.npy` **is required** and is
currently missing locally. It is not silently disabled or replaced by latent
scatter. Supply it before running baseline evaluation or fitting. Native DESI
blinding offsets are applied to exported star diagnostics without changing
physical predictions or unblinding the data. The notebook does not display
fitted cosmological parameters. The default policy still rejects blinded data
unless `blinding_policy: native` is explicitly selected.

`examples/validation_demo.yaml` and `examples/native_demo.yaml` retain the
previous small unblinded Karacayli2022 configuration solely as a scientific
regression fixture, with explicitly disabled emulator covariance. Its numerical
results do not validate the full CM2026 covariance or fit. No covariance or
trained model is generated by this implementation. The short MCMC run is not
a converged posterior, and latent-count convergence remains a production choice.

Weights, metadata, transforms, MPG training-domain/IGM summaries, Nyx IGM history
(currently required even for MPG by native cup1d), and public data must already
be configured. Do not retrain to use the interface.

## Optional DESI DR2 Lyα BAO check

The optional likelihood is Cobaya's built-in `bao.desi_dr2.desi_bao_lya`, using
the [official DESI DR2 Lyα defaults](https://github.com/CobayaSampler/cobaya/blob/master/cobaya/likelihoods/bao/desi_dr2/desi_bao_lya.yaml).
It is not enabled in the baseline examples. Install the official BAO data once:

```bash
cobaya-install bao.desi_dr2.desi_bao_lya --packages-path /path/to/cobaya_packages --just-data --no-set-global
python examples/evaluate_point.py examples/desidr2_lya_bao_only.yaml --packages-path /path/to/cobaya_packages
python examples/evaluate_point.py examples/cup1d_desidr2_lya_bao.yaml --packages-path /path/to/cobaya_packages
```

The BAO-only example varies H0 and needs neither ForestFlow weights nor its
missing covariance. The combined configuration retains the CM2026 P1D settings
and requires those assets. It shares **one CAMB provider**, and the command-line
output separates component log-likelihoods from their total. In the walkthrough,
set `USE_DESI_DR2_LYA_BAO = True` and, if needed, `BAO_PACKAGES_PATH`. P1D plots
continue to report P1D-only diagnostics; minimization uses the total likelihood.

For now this is a check using an **independence approximation**: no measured
P1D–BAO cross-covariance is included. CM2026 fixes the background parameters,
so BAO adds a constant with respect to its current sampled parameters, rather
than constraining As/ns or IGM coefficients. A broader joint analysis must
explicitly vary compatible background parameters and validate that approximation.
The optional overlay uses `additional_likelihoods` with `load_configuration`;
it deliberately does not replace the existing P1D likelihood. Pass this overlay
through the Python runner, not directly to `cobaya-run`.

## Interactive notebooks

The forward model batches ForestFlow coefficients and coalesces unique
redshift/k-grid requests into one native P1D array projection. Ragged grids
are padded with valid endpoint values and trimmed before observation handling.
The observation backend uses cup1d's columnar contaminant, resolution and
rebinning kernels; the correlated covariance contraction stays native.
Cobaya and Nelder–Mead still request one parameter point at a time. This is
not simultaneous evaluation of multiple optimizer points, and small packing,
ragged-grid and linear-interpolation loops remain. No measured speedup is
claimed solely from changing the execution path.

The CM2026 examples temporarily set `enforce_training_hull: false` at the
user's request. This permits unvalidated emulator extrapolation; rectangular
parameter priors, physical-input checks and spectrum/cosmology coverage
checks remain enforced. Restore this theory option to `true` to re-enable
the native pairwise training-hull check (the component default remains true).
Notebook minimization uses bounded, scaled, adaptive Nelder–Mead and retains
the best valid evaluation without treating a failed optimization as converged.

Install the optional notebook tools with `python -m pip install -e '.[notebooks]'`
from this repository, launch `jupyter lab`, and select the kernel from the
environment containing the sibling editable installs. Restart the kernel and
run cells in order. These notebooks require the same existing scientific assets
as the command-line demonstration; none retrains or writes scientific assets.

- [Likelihood walkthrough](notebooks/01_likelihood_walkthrough.py): evaluate
  a point, inspect derived quantities and emulator inputs, separate data likelihood
  from posterior, plot data/model panels at every redshift, optionally minimize,
  and replot the actual best-fitting point with cup1d's native renderers.
- [Parameters and caching](notebooks/02_parameters_and_caching.py): change
  nuisance, IGM and cosmology parameters, verify dependency reuse and cached
  restoration, and plot a small conditional likelihood slice.
- [Joint P1D + DESI DR2 Lyα BAO](notebooks/03_joint_p1d_desidr2_lya_bao.py):
  evaluate both components with one CAMB provider, plot the initial P1D model,
  optionally minimize the summed data likelihood and plot the best fit.
  Requires the optional BAO data installation above. The fixed CM2026
  background makes BAO a constant; the combination assumes independence.
- [Joint DESI DR1 cup1d + Vega Y3 mock](notebooks/04_joint_cup1d_vega_mock.py):
  vary `As`, `ns`, four mean-flux nodes, selected cup1d/Vega nuisances and
  `ap`/`at`; inspect shared Arinyo coefficients; plot both data branches;
  then optionally run a bounded joint minimization and replot its actual best
  valid point. This is a fixed-template, zero-cross-covariance smoke fit, not
  a consistency test between the two data sets.

These use the CM2026 configuration and its asset/numerical limitations described
above. The walkthrough's `RUN_MINIMIZATION` flag is off by default; enable it
to fit all sampled parameters without writing fit products. Jupytext pairs each notebook with a Python
source in `# %%` format, including Markdown cells. **Only `.py` sources belong in
Git**; `.ipynb` files and their outputs remain local and are ignored.

After a fresh clone, create the local notebooks (from the repository root):

```bash
jupytext --sync notebooks/*.py
```

The repository's `jupytext.toml` enables pairing. With Jupytext installed in the
Jupyter server environment, saving a notebook updates its `.py` partner. After
editing the Python source outside Jupyter, run the same `--sync` command, then
reload the notebook. Sync uses the newer file's inputs and preserves local
notebook outputs; avoid simultaneous unsynchronized edits to both partners.
In VS Code, use `--sync` or the Jupytext Sync extension rather than assuming
ordinary notebook saves synchronize automatically. See the
[Jupytext pairing documentation](https://jupytext.readthedocs.io/).

## Tests and documentation

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 pytest -q -m 'not scientific'
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 pytest -q -m scientific -s
```

Fast checks use explicitly synthetic fixtures; scientific checks use real CAMB,
weights, histories and observations. Missing assets are not successful validation.
